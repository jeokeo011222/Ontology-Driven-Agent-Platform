# contracts/02-统一错误码注册表

> **本文件是 ODAP 平台全部错误码的唯一真源。**
> 第一篇 `pkg/errors`、第四篇 `PluginError`、第九篇 Gateway 错误、第十篇总线错误**只允许引用本表，不得另行定义**。
> 新增错误码必须走 ADR；同一语义只允许一个码。版本：v1.0 · 2026-10-12

---

## 1. 设计原则

1. **两层结构**：12 个**基础码**（跨域通用，带 HTTP 映射与重试语义）+ 若干**域码**（域内具体语义，映射到唯一基础码）。API 响应同时返回两者：`code` = 域码（具体、稳定），`base_code` = 基础码（供客户端通用处理）。
2. **一语义一码**：`PERMISSION_DENIED` 过去在第一篇与第四篇各定义一次，现统一收编为域码 `AUTHZ_PERMISSION_DENIED`。
3. **`EXECUTION_UNKNOWN` 是安全码**：表示"平台未获得可信结果"，**永远不是失败**。任何超时/失联场景优先使用它，驱动对账而非重试。
4. **ERROR ≠ DENY**：授权决策三态为 `ALLOW`/`DENY`/`REQUIRE_APPROVAL`（第三篇），评估错误单独走 `EVAL_*`；`DENY` 是有意的安全拒绝，不记 `INTERNAL`。

## 2. 基础码（12 个，全平台唯一）

| 基础码 | HTTP | 可重试 | 需审计 | 含义与默认处理 |
|---|---|---|---|---|
| `INVALID_ARGUMENT` | 400 | 否 | 视域 | 请求参数/Schema 不符；修正输入，不重试 |
| `UNAUTHENTICATED` | 401 | 否 | 是 | 身份缺失或失效；引导重新认证 |
| `PERMISSION_DENIED` | 403 | 否 | **是（必记）** | 授权拒绝；记录决策 ID 与策略版本 |
| `NOT_FOUND` | 404 | 否 | 否 | 资源不存在或不在可见范围（不泄露存在性） |
| `CONFLICT` | 409 | 否 | 是 | 状态冲突/版本冲突/幂等键冲突/序号缺口 |
| `VALIDATION_FAILED` | 422 | 否 | 是 | 业务或语义校验失败（SHACL、输出契约、回执格式） |
| `RATE_LIMITED` | 429 | 是（尊重 Retry-After） | 否 | 限流；按退避策略重试 |
| `UNAVAILABLE` | 503 | 是（退避） | 否 | 依赖不可用（模型供应商、ERP、插件进程） |
| `RESOURCE_EXHAUSTED` | 429/503 | 有限 | 是 | 配额/预算/容量不足；不无限重试 |
| `DEADLINE_EXCEEDED` | 504 | 否 | 是 | 超过截止时间；**结果未知时升级为 `EXECUTION_UNKNOWN`** |
| `EXECUTION_UNKNOWN` | 202/409 | **否（走对账）** | **是（必记）** | 已 dispatch 但结果未确认；按幂等键对账，禁止盲目重发 |
| `INTERNAL` | 500 | 有限 | 是 | 平台内部错误；有限重试或隔离，告警 |

## 3. 域码注册表（收编各分册既有码）

### 3.1 通用/API 域（API）

| 域码 | 基础码 | 含义 | 来源 |
|---|---|---|---|
| `ONTOLOGY_VALIDATION_FAILED` | VALIDATION_FAILED | 本体校验未通过 | 总书 §3.3 收编 |
| `REQUEST_VALIDATION_FAILED` | INVALID_ARGUMENT | 请求格式/Schema 错误 | 新设 |

### 3.2 授权域（AUTHZ，第三篇）

| 域码 | 基础码 | 含义 |
|---|---|---|
| `AUTHZ_PERMISSION_DENIED` | PERMISSION_DENIED | 权限检查失败（合并第一篇/第四篇重复定义） |
| `AUTHZ_POLICY_EVALUATION_ERROR` | INTERNAL | 策略求值器内部错误（**不得**降级为 ALLOW） |
| `AUTHZ_APPROVAL_REQUIRED` | PERMISSION_DENIED | 决策为 REQUIRE_APPROVAL 而调用方未走审批流 |
| `AUTHZ_SCOPE_VIOLATION` | PERMISSION_DENIED | 数据范围/租户越界 |

### 3.3 插件域（PLUGIN，第四篇，原 9 码全部收编）

| 域码 | 基础码 | 默认处理 |
|---|---|---|
| `PLUGIN_INVALID_INPUT` | INVALID_ARGUMENT | 不重试，修正输入 |
| `PLUGIN_UNSUPPORTED_OPERATION` | INVALID_ARGUMENT | 不重试 |
| `PLUGIN_PERMISSION_DENIED` | PERMISSION_DENIED | 不重试，记审计 |
| `PLUGIN_DEPENDENCY_UNAVAILABLE` | UNAVAILABLE | 退避重试 |
| `PLUGIN_RATE_LIMITED` | RATE_LIMITED | 尊重退避 |
| `PLUGIN_DEADLINE_EXCEEDED` | DEADLINE_EXCEEDED | 视操作类型；有副作用时转 `EXECUTION_UNKNOWN` |
| `PLUGIN_RESOURCE_EXHAUSTED` | RESOURCE_EXHAUSTED | 不立即无限重试 |
| `PLUGIN_INTERNAL_ERROR` | INTERNAL | 有限重试或隔离 |
| `PLUGIN_RESULT_INVALID` | VALIDATION_FAILED | 隔离结果并记录诊断 |

### 3.4 模型域（MODEL，第九篇）

| 域码 | 基础码 | 含义 |
|---|---|---|
| `MODEL_DATA_POLICY_DENIED` | PERMISSION_DENIED | 数据分级禁止发送该模型；不能靠换未批准模型规避 |
| `MODEL_BUDGET_EXCEEDED` | RESOURCE_EXHAUSTED | 预算不足，停止新增调用 |
| `MODEL_CAPABILITY_UNAVAILABLE` | UNAVAILABLE | 无合格模型支持所需能力 |
| `MODEL_OUTPUT_INVALID` | VALIDATION_FAILED | 输出未过五层校验（受限重生成 ≤N 次后仍失败） |
| `MODEL_PROVIDER_UNAVAILABLE` | UNAVAILABLE | 供应商不可用/熔断中 |

### 3.5 总线域（BUS，第十篇）

| 域码 | 基础码 | 含义 |
|---|---|---|
| `BUS_CAPACITY_EXCEEDED` | RESOURCE_EXHAUSTED | 队列或预算已满；过载时明确返回，不得伪造成功 |
| `BUS_DUPLICATE_EVENT` | CONFLICT | Inbox 去重命中（幂等成功路径，非错误场景时记 INFO） |
| `BUS_SEQUENCE_GAP` | CONFLICT | 序号缺口超过等待窗口，触发恢复重读 |

### 3.6 ERP 域（ERP，第七篇）

| 域码 | 基础码 | 含义 |
|---|---|---|
| `ERP_OPERATION_UNKNOWN` | EXECUTION_UNKNOWN | 超时/失联，结果未知；走对账 |
| `ERP_RECEIPT_INVALID` | VALIDATION_FAILED | 回执格式/签名校验失败 |
| `ERP_IDEMPOTENCY_CONFLICT` | CONFLICT | 同键不同 payload |
| `ERP_ADAPTER_UNAVAILABLE` | UNAVAILABLE | 连接不可用（按 L1/L2/L3 能力分级处理） |
| `ERP_BUSINESS_REJECTED` | VALIDATION_FAILED | 远端业务规则拒绝（非平台错误） |

## 4. 命名与登记规则

1. 命名：`<域>_<对象>_<条件>`，全大写蛇形；域前缀取值 `API/AUTHZ/PLUGIN/MODEL/BUS/ERP/RUN/ONT/EVAL/DATA`。
2. 登记：新码必须在本表登记（域码表新增一行 + 基础码映射），未登记的码不允许出现在任何代码、Schema 或文档中。
3. 响应结构（统一，第一篇 §5 错误契约扩展）：

```
{
  "error": {
    "code": "ERP_OPERATION_UNKNOWN",
    "base_code": "EXECUTION_UNKNOWN",
    "message": "操作结果尚未确认，已转入对账",
    "retryable": false,
    "details": { "operation_id": "op_001", "reconciliation_id": "rec_9" }
  },
  "request_id": "req_456"
}
```

4. `message`/`details` 必须脱敏（总书 §3.3）：不泄露内部提示词、密钥、其他租户信息。
5. CI 门禁（`tools/contract-lint`）：全仓库（代码常量、JSON Schema enum、文档表格）出现的错误码必须能在本表检索到；一码一义，禁止同义不同码。
