# contracts/01-全局状态注册表

> **本文件是 ODAP 平台全部状态词表的唯一真源（single source of truth）。**
> 各分册、数据库 DDL、事件 Schema、前端标签**只允许引用本表，不得另行定义**。
> 新增或修改状态必须走 ADR 流程，并同步更新：本表 → 受影响分册 → DDL 迁移 → 前端标签映射 → 契约测试。
> 版本：v1.0 · 2026-10-12 · 权威来源：第六篇（Harness 状态机为执行域权威）

---

## 1. Run 状态（agent_runs.status）

权威定义见第六篇 §3.1 与 §14.2 转换矩阵，共 **17 个状态**：

| 状态 | 常量名 | 是否终态 | 可调度队列 | 一句话含义 |
|---|---|---|---|---|
| `CREATED` | RunCreated | 否 | 执行 | 已创建，等待初始化 |
| `CONTEXT_BUILDING` | RunContextBuilding | 否 | 执行 | 正在构建运行上下文 |
| `READY` | RunReady | 否 | 执行/规划 | 上下文已固定，可规划或执行 |
| `PLANNING` | RunPlanning | 否 | 否 | Agent 正在生成执行计划 |
| `PLAN_VALIDATING` | RunPlanValidating | 否 | 否 | 计划结构/依赖/风险校验中 |
| `RUNNING` | RunRunning | 否 | 执行 | 正在执行步骤 |
| `WAITING_INPUT` | RunWaitingInput | 否 | 否 | 等待用户补充信息 |
| `WAITING_APPROVAL` | RunWaitingApproval | 否 | 否 | 等待人工审批 |
| `PAUSED` | RunPaused | 否 | 否 | 用户或管理员主动暂停 |
| `RECOVERING` | RunRecovering | 否 | 执行（仅恢复工作） | 正在恢复任务或核对外部结果 |
| `CANCELLING` | RunCancelling | 否 | 取消收敛 | 取消已受理，等待在途外部操作收敛 |
| `REQUIRES_RECONCILIATION` | RunRequiresReconciliation | 否 | 对账 | 存在结果未知的外部操作 |
| `MANUAL_REVIEW` | RunManualReview | 否 | 否 | 需人工介入才能安全继续 |
| `COMPLETED` | RunCompleted | **是** | 否 | 任务按定义成功完成 |
| `FAILED` | RunFailed | **是** | 否 | 任务终止且无法继续 |
| `CANCELLED` | RunCancelled | **是** | 否 | 取消完成且无未处理执行风险 |
| `EXPIRED` | RunExpired | **是** | 否 | 超过允许的生命周期 |

## 2. Step 状态（run_steps.status）

权威定义见第六篇 §4.1，共 8 个：

`PENDING` → `READY` → `RUNNING` → {`SUCCEEDED`, `FAILED`, `CANCELLED`, `UNKNOWN`}；
`RUNNING` 可经 `RETRY_WAIT` 回到 `READY`；`RUNNING`/`RETRY_WAIT` 可进 `WAITING_INPUT`/`WAITING_APPROVAL`（解决后回 `RUNNING`）；`UNKNOWN` 进 `RECONCILING`（对账后定 `SUCCEEDED`/`FAILED`/`MANUAL_REVIEW`）。

| 状态 | 终态 | 说明 |
|---|---|---|
| `PENDING` | 否 | 依赖未满足 |
| `READY` | 否 | 依赖已满足 |
| `RUNNING` | 否 | 执行中 |
| `RETRY_WAIT` | 否 | 等待符合策略的重试 |
| `WAITING_INPUT` | 否 | 等待用户输入 |
| `WAITING_APPROVAL` | 否 | 等待审批 |
| `SUCCEEDED` / `FAILED` / `CANCELLED` / `SKIPPED` | 是 | 步骤终态 |
| `UNKNOWN` | 否 | 结果暂时无法确定 |
| `RECONCILING` | 否 | 对账中 |

## 3. Tool Call 状态（tool_calls.status）

权威定义见第二篇 §6.3 DDL，共 12 个：

`PENDING` → `VALIDATING` → {`REJECTED`, `WAITING_APPROVAL`, `READY`} → `DISPATCHED` → `EXECUTING` → {`SUCCEEDED`, `FAILED`, `UNKNOWN`}；`UNKNOWN` → `RECONCILING` → {`SUCCEEDED`, `FAILED`, `MANUAL_REVIEW`}。

## 4. External Operation 状态（erp_operations.status）

权威定义见第七篇 §7，共 9 个：

`PENDING` → `DISPATCHED` → `EXECUTING` → {`SUCCEEDED`, `FAILED`, `UNKNOWN`}；`UNKNOWN` → `RECONCILING` → {`SUCCEEDED`, `FAILED`, `MANUAL_REVIEW`, `COMPENSATED`}。

## 5. 跨层等价与禁忌

1. **任务状态 ≠ 业务状态**：Run = `COMPLETED` 而 ERP Operation = `UNKNOWN` 是合法组合（总书 §4.6）。任何 UI 与 API 不得把 Run 终态翻译成"业务已成功"。
2. **禁止同义反复**：上层不得发明 `WAITING_RECONCILIATION`、`PENDING_RECONCILE`、`TO_RECONCILE` 等等价词；查表无此状态即为不存在。
3. **前端标签是投影不是状态**：第十七篇的中文标签（运行中/待审批/待对账/已取消…）只允许由本表状态聚合派生，聚合规则见第十七篇 §11.2 状态组件，派生逻辑放服务端。
4. **事件名 ≠ 状态名**：事件（如 `CancellationRequested`）触发转换，但事件本身不是状态；两层词表分开维护（第六篇 §3.3 / §14.1）。

## 6. 一致性门禁（CI）

`tools/contract-lint` 必须断言：

1. 各分册/Docker/前端代码中出现的状态枚举 ⊆ 本表集合（白名单校验，大小写不敏感但统一大写蛇形）。
2. 本表每个状态在第六篇 §14.2 矩阵中至少出现一次（作为行或列目标）。
3. DDL 的 CHECK 约束集合与本表集合逐项相等（防止 schema 漂移）。
4. 前端标签映射表覆盖本表全部 17 个 Run 状态（含终态）。
