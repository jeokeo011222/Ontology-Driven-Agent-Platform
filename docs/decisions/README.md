# 架构决策记录（ADR）索引

ADR 记录**已经做出且会影响后续实现**的技术决策及其取舍。
它与设计书的区别：设计书描述"系统长什么样"，ADR 记录"为什么是这一版而不是另一版"。

## 何时需要新增 ADR

满足任一条件即应落 ADR：

1. 引入或替换一项外部依赖（数据库、图存储、消息中间件、LLM 供应商）。
2. 改变跨模块接口形状（契约、事件 Schema、Port 定义）。
3. 为了性能或交付节奏**偏离**设计书既定方案。
4. 需要在两种方案间做不可逆取舍。

## 撰写要求

- 编号连续：`ADR-00N-<短标题>.md`。
- 必须写明：背景、备选方案、决策、后果（含何时应重新评估）。
- 决策若被推翻，**不删除**原 ADR，改为在其头部标记 `Superseded by ADR-XXX` 并附原因。
