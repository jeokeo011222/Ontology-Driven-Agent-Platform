# 本体分类合并为「业务领域分类」+ AI 生成本体支持本地文档上传

## 1. 背景与目标

用户在最新请求中提出两件事：

1. **本体分类改为业务领域分类，和本体页面合并，属于基础字典。**
2. **企业本体页面 → AI 自动生成本体弹窗**：制度文档路径改成「可从本地选择 word / excel / MD 文件」；
   「业务领域」改用读取字典，不允许手工录入。

拆解为两个可交付能力：

- **能力 A（信息架构）**：把独立的 `本体分类` 页面（`/admin/ontology-categories`）改名为
  `业务领域分类`，以**页内 Tab** 的形式并入 `企业本体` 页面；导航上把合并后的页面从
  「语义与数据」分组迁到新增的「基础字典」分组。
- **能力 B（生成入口）**：AI 自动生成弹窗支持**本地文件上传**（`.docx/.doc/.xlsx/.md`），
  并保留折叠的「服务端路径」高级项；「业务领域」由**读取字典**的下拉框选定，
  不再提供自由文本输入。

```go
// saveUpload 把一个上传文件落盘到 uploadsRoot 下，返回绝对路径与用于审计/回显的名字。
// 名字 = <uuid>_<净化后的原始文件名>，避免同名覆盖与路径穿越。
func (h *Handler) saveUpload(fh *multipart.FileHeader) (full string, name string, err error) {
	orig := filepath.Base(strings.ReplaceAll(fh.Filename, "\\", "/"))
	ext := strings.ToLower(filepath.Ext(orig))
	if !supportedUploadExt[ext] {
		return "", "", errors.Ef(errors.CodeInvalidArgument,
			"不支持的文件类型 %s（仅支持 .docx/.doc/.xlsx/.md）", ext)
	}
	root, err := filepath.Abs(h.uploadsRoot())
	if err != nil {
		return "", "", errors.Wrap(err, errors.CodeInternal, "上传目录不可解析")
	}
	if err := os.MkdirAll(root, 0o755); err != nil {
		return "", "", errors.Wrap(err, errors.CodeInternal, "上传目录不可创建")
	}
	rel := ids.New().String() + "_" + orig
	full = filepath.Join(root, rel)
	dst, err := os.Create(full)   // O_EXCL 语义：uuid 前缀保证不冲突
	if err != nil {
		return "", "", errors.Wrap(err, errors.CodeInternal, "上传文件写入失败")
	}
	defer dst.Close()
	src, err := fh.Open()
	if err != nil {
		return "", "", errors.Wrap(err, errors.CodeInternal, "上传文件读取失败")
	}
	defer src.Close()
	if _, err := io.Copy(dst, src); err != nil {
		return "", "", errors.Wrap(err, errors.CodeInternal, "上传文件保存失败")
	}
	return full, orig, nil
}
```

#### P1-1 `web/src/api/client.ts` —— 新增 `apiUpload`

在 `apiPost` 等便利方法旁新增（**不设置 `Content-Type`**，由浏览器生成 multipart boundary）：

```ts
/**
 * multipart 上传（FormData）。与 execute 同样注入 Bearer 与 Idempotency-Key，
 * 但**不**设置 Content-Type —— 必须让浏览器自动带上 multipart 边界。
 * 刻意不走 fixtures：上传无法用静态样例覆盖。
 */
export async function apiUpload<T>(
  path: string,
  form: FormData,
  options: RequestOptions = {},
): Promise<T> {
  const headers: Record<string, string> = { Accept: 'application/json', ...options.headers };
  const token = getSessionToken();
  if (token && !options.headers?.Authorization && !options.headers?.authorization) {
    headers['Authorization'] = `Bearer ${token}`;
  }
  if (options.idempotencyKey) headers['Idempotency-Key'] = options.idempotencyKey;

  let response: Response;
  try {
    response = await fetch(buildUrl(path, options.query), {
      method: 'POST',
      headers,
      credentials: 'same-origin',
      body: form,
      signal: options.signal,
    });
  } catch (error) {
    if (isAbortError(error)) throw error;
    throw new ApiError({
      code: TRANSPORT_ERROR_CODE,
      baseCode: 'UNAVAILABLE',
      message: '网络请求失败或超时，未取得服务端响应。',
      retryable: true,
      status: 0,
      transport: true,
      unknownOutcomeHint: true,
    });
  }

  if (response.status === 204) return undefined as T;
  const text = await response.text();
  let payload: unknown = null;
  if (text.length > 0) {
    try { payload = JSON.parse(text); } catch { payload = { raw: text }; }
  }
  if (!response.ok) throw toApiError(response.status, payload);
  return payload as T;
}
```

```ts
    if (body.description) form.append('description', body.description);
    if (body.category_id) form.append('category_id', body.category_id);
    if (body.model_id) form.append('model_id', body.model_id);
    if (body.max_source_chars) form.append('max_source_chars', String(body.max_source_chars));
    const f = body.source_file;
    return apiUpload<GenerateOntologyResult>('/ontologies/generate', form, {
      idempotencyKey: newIdempotencyKey(`onto-generate-${f.name}-${f.size}-${f.lastModified}`),
```

## 4. 假设与决策

| # | 决策 | 理由 |
| --- | --- | --- |
| D5 | 上传走 **multipart**，而非 base64+JSON | `decodeJSON` 的 `io.LimitReader(1MiB)` 会**静默截断**，base64 大文件必然被误报「不是合法 JSON」；放宽全局 `maxBodyBytes` 会同时放大所有 JSON 端点的 DoS 面。multipart 另设 32 MiB 上限，隔离风险 |
| D6 | 上传落盘到**新的可写目录** `ODAP_UPLOAD_ROOT`（默认 `var/uploads`） | `docs/资料` 为 `:ro` 挂载，不可写；且语料目录语义上是仓库资产，混入用户上传会污染语料根 |
| D7 | 上传扩展名仅 `.docx/.doc/.xlsx/.md` | 需求限定「word、excel 或 MD」；与 `docingest` 支持集取交集（`.xls` 不被 docingest 支持，接收后必然抽取失败，故前置拒绝） |
| D8 | `file` 与 `source_path` **严格二选一**，同时/都不提供 = 400 | fail-closed；避免「两个来源都给了，服务端悄悄选一个」的静默歧义 |
| D9 | 业务领域 `domain` **由所选分类的 `category_code` 派生**，并在后端校验一致性 | 满足「业务领域改用读取字典，不允许录入」；同时 `category_id` 仍照常提交，保住既有 409 门禁与计数 |
| D10 | 业务领域下拉**不设为必填** | 字典为空（全新租户）时不阻断生成；缺省仍为 `general`，与改造前行为一致 |
| D11 | 上传文件**保留落盘**不删除 | 作为生成输入的追溯证据；uuid 前缀避免同名覆盖 |
| D12 | nginx `client_max_body_size 32m` 与后端上限对齐 | 否则默认 1m 会在 api 之前 413，表现为「上传大文件必然失败」且后端日志无痕 |
