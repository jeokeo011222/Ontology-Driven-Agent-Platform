# 业务工作台本体化改造方案

## Context（为什么改）

「业务工作台」目前是**以 Agent 为中心**的，与产品定位（以企业本体驱动业务）错位，并暴露出若干既有缺陷：

| 现状 | 证据 |
| --- | --- |
| 「业务应用」页展示的是 **Agent 投影**，不是本体 | [audit_aggregate.go](file:///d:/Code/Ontology-Agent/internal/api/store/audit_aggregate.go#L149-L175) `Apps()` 查 `registry.agents` |
| 「AI 业务助手」**没有本体选择**，且提交必然 400 | 前端发 `{objective, business_type}`（[assistant/api.ts](file:///d:/Code/Ontology-Agent/web/src/features/assistant/api.ts#L15-L31)），后端要求 `agent_version_id`（[runs.go](file:///d:/Code/Ontology-Agent/internal/api/handlers/runs.go#L14-L21)） |
| 助手页「结构化执行计划」是**硬编码静态列表** | [AssistantPage.tsx](file:///d:/Code/Ontology-Agent/web/src/features/assistant/pages/AssistantPage.tsx#L137-L142) 四条固定 `<li>`，而页头注释声明「不伪造推理进度」 |
| 任务详情「执行过程」页签**恒 404** | 前端调 `GET /runs/{id}/steps`（[tasks/api.ts](file:///d:/Code/Ontology-Agent/web/src/features/tasks/api.ts#L35-L41)），但 [router.go](file:///d:/Code/Ontology-Agent/internal/api/router.go#L51-L57) 未登记该路由 |
| Run 表**没有** objective / ontology 绑定 | `runtime.agent_runs` 要求 `agent_version_id NOT NULL`，无本体列（[000005](file:///d:/Code/Ontology-Agent/migrations/platform/000005_create_execution.sql#L7-L51)） |

**目标结果**：管理端设计了多少个本体，业务助手页就显示多少个可选本体；用户提交业务需求后，由大模型**基于该本体规则**审查并给出结论；任务详情可见**基于本体的处理过程**；业务应用页显示本体而非智能体。

**已确认的决策**（用户选择）：
1. 本体规则审查**同步在提交请求内完成**（复用现成引擎，不新建 Worker 执行器）。
2. 业务应用页**仅显示本体**。
3. **扩展现有 `POST /runs`**（`agent_version_id` 变可选，新增 `ontology_id`/`objective`），不新增创建入口。
4. 审查结论为「不合规」时 Run 转 **MANUAL_REVIEW**（绝不伪装成通过，也不直接判失败）。

**可复用的真实能力**（不新造轮子）：
- `store.OntologyVersionSnapshot` → 取本体最新版本快照（`ontologyID/versionID/ontologyKey/version/manifest`）。
- `graphload`：`NewNamespace` / `ParseManifest` / `Manifest.BuildShapes` / `Manifest.TBox` / `Manifest.ABox` / `Manifest.TargetClassIRIs` / `GraphIRI` / `CountTypedNodes`。
- `graphstore.GraphStore.InsertTriples`（经 `h.deps.GraphStore`）。
- `shacl.Validate` → `Report{Conforms, Results}`（权威规则结论）。
- `callLLM` / `h.llmGateway()`（受治理网关：限流+预算+缓存+路由+结构化输出）。
- `harness.Machine.Apply`（真实状态机，配合 `h.deps.Machine`）。
- 参照实现模板：[ontologies.go](file:///d:/Code/Ontology-Agent/internal/api/handlers/ontologies.go#L103-L270) `ValidateOntology`（含**反假绿探针**：命中目标类实例数为 0 时拒绝给结论）。

## 实现步骤

### 1. 迁移 `migrations/platform/000035_run_ontology_binding.sql`（下一个空闲编号）
对 `runtime.agent_runs`：
- 新增 `objective TEXT`、`business_type TEXT`、`ontology_version_id UUID`、`plan JSONB`、`review_conclusion JSONB`。
- `ALTER COLUMN agent_version_id DROP NOT NULL`（本体驱动 Run 无 Agent；FK 对 NULL 天然允许）。
- 索引 `idx_agent_runs_ontology (tenant_id, ontology_version_id)`。
- 每列加 `COMMENT ON COLUMN` 说明语义（含「review_conclusion 由服务端确定性合成，模型不得覆盖 SHACL 结论」）。
- 该表 owner 已是运行角色，无需额外授权（仅有 ALTER，无新建 schema）。

### 2. store 层（`internal/api/store/runs.go`）
- `Run` 增字段：`Objective *string`、`BusinessType *string`、`OntologyVersionID *string`、`Plan json.RawMessage`、`ReviewConclusion json.RawMessage`；`runColumns` 增对应列（jsonb 一律 `::text`），`MarshalJSON` 增 `plan`/`review_conclusion` 两个 `json.RawMessage` 出口（沿用既有 `rawJSON()`）。
- `CreateRunInput` 增：`Objective`、`BusinessType`、`OntologyVersionID *ids.ID`、`Steps []RunStepInput`、`Dependencies []RunDependencyInput`。
- `CreateRun`：
  - 校验改为「`AgentVersionID` 与 `OntologyVersionID` 至少一个非空」，二者皆空才报 `INVALID_ARGUMENT`。
  - `agent_version_id` 用 `nullableID(...)` 写 NULL。
  - 在同一 `TenantTx` 内依次插入 run → `runtime.run_steps` → `runtime.agent_run_dependencies`（`ONTOLOGY_VERSION`，`dep_digest` 取 manifest 摘要）——**单事务原子**。
- 新增 `RunStepInput` / `RunDependencyInput` 结构体与插入 SQL（列：step_no/step_type/status/result_payload/evidence_refs/started_at/finished_at/error_code/error_summary）。
- 新增 `runStepView(row)` 映射：把 `runtime.run_steps` 行映射为契约视图（供 `/runs/{id}` 与 `/runs/{id}/steps` 共用），保留 `result_payload` 原样透出。
- `audit_aggregate.go` 的 `Apps()` 改为**本体投影**：`ontology.ontologies`（`status <> 'DELETED'`）LATERAL 取最新版本；返回 `id/ontology_key/name/domain/description/status/latest_version/latest_version_status`。
- 新增 `ListWorkspaceOntologies(ctx, limit, cursor)`（业务口径的本体列表，复用 `ListOntologies` 同一 SQL 与分页编码）。

### 3. handler 层
**`internal/api/handlers/runs.go`**
- `createRunRequest` 增 `OntologyID`、`Objective`、`BusinessType`；`agent_version_id` 变为可选（非空才解析 UUID，保持原错误文案）。
- `CreateRun` 分支：
  - 有 `ontology_id` → 走**本体驱动审查**（新文件 `internal/api/handlers/ontology_review.go`）。
  - 无 `ontology_id` → 沿用现有 Agent 驱动行为（零回归）。
- `GetRun`：`steps` 改为返回视图（`seq/name/kind/...`），并带上 run 的 `objective`/`ontology_version_id`/`plan`/`review_conclusion`。
- 新增 `ListRunSteps` handler（`GET /api/v1/runs/{id}/steps`），与 `GetRun` 的 steps 同构。

**`internal/api/handlers/ontology_review.go`（新增，核心）**
`reviewByOntology(ctx, id, ontologyID, objective) → (*Run, error)`，链路每步都真实执行、失败即明确报错：
1. `h.deps.GraphStore == nil` → 503 UNAVAILABLE（同 `ValidateOntology` 口径：无图存储就无法给结论）。
2. `h.llmGateway()` 未装配 → 503 UNAVAILABLE（**不建 Run、不伪造结论**）。
3. `OntologyVersionSnapshot` → `NewNamespace` → `ParseManifest` → `BuildShapes`。
4. `len(parsed.Shapes) == 0` → 422《本体未定义 SHACL 形状，规则不可执行》（拒绝给出无意义「通过」）。
5. **LLM 调用（受治理网关）**：system prompt 由本体真实词表渲染（类 / 属性 / 关系 / 枚举 / 各 shape 及其约束项），user 为业务目标；`ResponseSchema` = 新常量 `ontologyReviewSchema`（`additionalProperties:false`，字段白名单：`facts[]`(class/id/properties)、`decision`(enum APPROVE/REJECT/NEED_INFO/NEED_APPROVAL)、`reasons[]`、`rule_checks[]`(shape_id/outcome/evidence)），数组设上限防截断。
6. 由 `facts` 构造 ABox 三元组（`ns.InstanceIRI`），与 `TBox` 一起插入 **Run 专属命名图** `graphIRI = GraphIRI(key, "run-"+runID)`（用独立图，避免污染本体校验图）。
7. **反假绿探针**：`CountTypedNodes(..., targets)` 为 0 → 422《图中没有可校验实例》，拒绝给结论。
8. `shacl.Validate` → 权威 `Report{Conforms, Results}`。
9. **确定性结论合成（模型不得覆盖 SHACL）**：`!Conforms` 或 `decision ∈ {REJECT, NEED_INFO}` → `NEED_INFO` + `MANUAL_REVIEW`；`Conforms && APPROVE` → `APPROVE` + `COMPLETED`；`Conforms && NEED_APPROVAL` → `NEED_APPROVAL` + `MANUAL_REVIEW`。
10. 组装 `runtime.run_steps`（6 行，`status` 取真实结果，`result_payload` 带真实数据）：
    `CONTEXT_BUILD`(本体词表) → `ONTOLOGY_EXTRACT`(模型事实) → `GRAPH_LOAD`(图 IRI + 三元组条数) → `SHACL_VALIDATE`(conforms + focus_nodes + findings 摘要) → `RULE_REVIEW`(模型 decision + rule_checks) → `CONCLUSION`(最终结论与依据)。
    每步的 `result_payload` 显式携带前端所需的 `rationale` / `ontology_version` / `rule_refs` / `fact_refs`（对应 [TaskDetailPage.tsx](file:///d:/Code/Ontology-Agent/web/src/features/tasks/pages/TaskDetailPage.tsx#L258-L282) 已实现的渲染）。
11. 落库：`CreateRun`（单事务：run + steps + dependency），`status='CREATED'`。
12. `h.deps.Machine.Apply` 按**合法矩阵**推进到终态（不新增事件，31 事件数不变）：
    `ContextBuildStarted → ContextBuildSucceeded → PlanGenerated → PlanValidationSucceeded → PlanValidationSucceeded → (RunCompleted | ManualInterventionRequired)`。
    `RunCompleted` 的 facts 需 `LeaseValid:true, HasInflightExternalOps:false, AllStepsTerminal:true, HasUnknownToolCalls:false, OutputContractValidated:true`。`Machine == nil` → 503。
13. `h.recordAudit(...)` + `h.publish(...)` 广播 `RunCreated` / 结论事件。

**`internal/api/handlers/bff.go` / `workspace.go`**
- 新增 `WorkspaceOntologies` handler（`GET /api/v1/workspace/ontologies`，仅 `h.identity(r)`，权限口径同 `workspace.view`），返回与 `Apps()` 同构的本体列表，供助手页本体下拉使用。

**`internal/api/router.go`**
- 增 2 条路由：`GET /api/v1/runs/{id}/steps`、`GET /api/v1/workspace/ontologies`。

### 4. 契约 `contracts/openapi.yaml`
- `CreateRunRequest`：required 去掉 `agent_version_id`；增 `ontology_id`、`objective`、`business_type`；描述写明「`ontology_id` 与 `agent_version_id` 二选一，本体驱动时同步返回已完成审查的 Run」。
- `Run`：增 `objective` / `business_type` / `ontology_version_id` / `plan` / `review_conclusion`；`agent_version_id` 加 `nullable: true`。
- 新增 `RunStepView` schema（前端视图字段），`RunStepList`，并新增 path `/runs/{id}/steps`（200）。
- 新增 path `/workspace/ontologies`（200 `AppList`）。
- `App`：`agent_key` → `ontology_key`，并增 `name`。
- 新增 path `/runs/{id}/steps` 后，前端 `useRunSteps` 的 GET 调用自动满足门禁（门禁 ⑤ 只校验**写**方法，不会误伤）。

## 边界与已知遗留

- `GET /api/v1/runs/{id}/erp-operations` 仍是**未登记路由**（前端任务详情的「外部操作与对账」页签会显示该项加载失败）。属既有契约缺口，**不在本次需求范围**，保持现状不改，仅在此标注。
- Worker 仍是调度骨架；本次审查为**同步执行**，因此不需要 Worker 具备步骤执行能力。若后续要做异步化，应另立任务（新增执行器 + 事件推进 + 失败重试/对账），本方案不涉及。
- 全程 fail-closed：模型未装配 / 输出非法 JSON / 本体无形状 / 图中无实例 → 一律明确报错，绝不静默降级或伪造结论。
