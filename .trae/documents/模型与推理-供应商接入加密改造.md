# 模型与推理：供应商接入条目 + 密钥加密存储与打码显示

## Context（为什么要改）

用户对「模型与推理」页面提出了明确的设计不满，并给出三条设计要求：

1. 点「新建供应商」弹出窗口，录入大模型供应商信息（**窗口内附带测试连接功能**）。
2. 录入完毕后展示**大模型列表**，可对该条目进行**修改 / 删除**。
3. **api-key 必须加密存储、并且以打码方式显示**。

现状与要求的三处冲突：

- **凭据只能靠环境变量**：`llm.endpoints` 只存 `credential_ref`（变量名），实际密钥必须预先写进进程环境（`.env` → 容器 env）。用户在界面上无法录入密钥，只能"先去改部署环境再回来"——这与"录入窗口录完即可用"的要求不符。
- **列表是两张分离的表**：页面把「供应商」与「端点」拆成两个 section，用户要在两个表之间来回跳（先建供应商→再给供应商加端点→再编辑端点填地址）。用户要的是**一行 = 一条供应商接入条目**（供应商 + 首个端点 + 密钥，新建时一次录完）。
- **没有测试能力**：装配是**进程启动期一次性**完成的，UI 保存后必须重启 API 才生效（`cmd/api/main.go:187-189`）。用户无法在录入时立刻知道"这个 base_url + key 到底能不能打通"。

同时，现行硬约束「密钥只以 env 注入、数据库仅存引用名、明文永不落盘」正是要解决的问题本身——用户已明确推翻它，改为「**新增密文列，并保留 env 引用路径（密文优先）**」。

### 已确认的口径（用户已决策，不再重开）

| 项 | 决策 |
|---|---|
| 列表口径 | **供应商接入条目**（每行 = 供应商 + 首个端点 + 密钥；新建弹窗一次录完；行内可改/删）。**不要求**新建 `model_revisions` 管理 API |
| 凭据存储 | **新增密文列（AES-256-GCM），并保留 `credential_ref` 环境变量引用路径；解析时密文优先** |
| 测试按钮 | 用弹窗里**刚填的参数真实试调一次**，**不落库、不写账本** |
| 打码显示 | **「已配置」+ 末 4 位**（如 `sk-****6e22`） |

### 决定性的既有事实（探索已核实）

- **F1 装配冻结**：生成网关与推理网关只在进程启动时装配一次（`cmd/api/main.go:187-189` → `cmd/api/llm_gateway.go:22`；无 reload 循环）。→ **UI 保存后需重启 API 才参与路由**，页面必须明示这一点（不实现热重载，超出本次范围）。
- **F2 仓库无任何加解密能力**：全仓 grep `crypto/aes|cipher|Encrypt|Decrypt|pbkdf2|scrypt` 只命中 `crypto/rand`（`requestid.go`/`session.go`/`ids.go`）。→ 必须新建 `secretbox` 包，不能假设已有工具。
- **F3 `newProvider` 三重硬要求**：`internal/llm/registry.go:402-421` 对 HTTP 端点要求 `base_url` 非空 + `credential_ref` 非空 + `getenv(ref)` 非空，否则该端点被排除（fail-closed）。
- **F4 `model_revisions` / `capability_profiles` 无任何 API**：全仓只有 `internal/seed/apply.go:331,362` 写入。→ 新建的供应商其端点处于「无模型版本 → 不参与路由」的**合法中间态**，列表必须显式标注该徽标（不得让用户以为"建好就能用"）。
- **F5 审计表带哈希链**：`audit.audit_events` 的 `event_payload` 一旦写入即永久留痕。→ **明文密钥绝不能进审计/SSE**，这是最严重的泄密面。
- **F6 PostgreSQL 会记录语句参数**（`log_statement`/`pg_stat_statements`/`pg_stat_activity`）→ **加密必须先于 SQL**：明文绝不可作为 SQL 参数出现。这是"在 store 层加密"而非 SQL 内 `pgcrypto` 的决定性理由。
- **F7 路由单一真源**：`internal/api/router.go:170-177` 的 `routes(h)`；新增路由必须**同步三处**：`router.go`、`internal/api/router_test.go` 的 `contractEndpoints`、`contracts/openapi.yaml`。漏一处会让 `make gates` 报"路由不可达"的误导性错误。
- **F8 无逐路由权限中间件** → 前端 `PermissionGate`（`admin.model.write`，已登记于迁移 `000024`）是当前唯一权限门。
- **F9 迁移最大编号 = `000028`** → 新迁移取 `000029`。

## 推荐方案

### 总体思路

分三条线一次做完：

1. **加密层**（新 `secretbox` 包 + 主密钥 env）：把密钥从界面安全地送到库里。
2. **数据层**（迁移 000029 加列 + store 层写入时加密、读取时只回打码值）：明文字节永不进 SQL 参数、永不进审计。
3. **交互层**（前端一行一条接入条目 + 弹窗内含非阻塞「测试连接」）：满足用户三条设计要求。

### P0 —— `secretbox` 加密包（新建）

**新建** `internal/platform/secretbox/secretbox.go`：

- 信封格式：`version(1B=0x01) || nonce(12B) || ciphertext+tag`，算法 AES-256-GCM。
- AAD（附加认证数据）：`"llm.endpoints.credential_ciphertext\x00" + endpoint_id`。绑定端点 ID 可防止"把 A 端点的密文搬到 B 端点"。
- 导出 API：
  - `type Cipher struct { aead cipher.AEAD }`
  - `func DecodeMasterKey(s string) ([]byte, error)` —— 接受 base64（32 字节）或 64 位 hex。
  - `func NewFromEnv(getenv func(string) string) (*Cipher, error)` —— 读 `ODAP_SECRET_MASTER_KEY`；**空值返回 nil, nil**（表示"未配置主密钥"，由调用方 fail-closed 处理，不 panic）。
  - `func New(key []byte) (*Cipher, error)`
  - `func (c *Cipher) Encrypt(plaintext []byte, aad []byte) ([]byte, error)`
  - `func (c *Cipher) Decrypt(envelope []byte, aad []byte) ([]byte, error)`
  - `func AADFor(endpointID string) []byte`
  - `func Mask(secret string) string` —— 打码规则：空→`""`；长度 < 8 → `"****"`；否则
    `prefix + "****" + 末4位`，其中 `prefix` 取"下标 1..4 范围内首个 `-` 之前的部分"（如 `sk-4376...` → `sk-****6e22`）。
- **新建** `internal/platform/secretbox/secretbox_test.go`：信封 round-trip、AAD 换端点必失败、篡改密文必失败、短密钥打码、非法主密钥报错、未配置主密钥返回 nil。

**修改** `internal/platform/config/config.go`：

- `Config` 结构体（`config.go:12-48`）新增字段 `SecretMasterKey string`。
- `Load`（`config.go:51-71`）新增 `SecretMasterKey: os.Getenv("ODAP_SECRET_MASTER_KEY")`。**不设为必填**（避免存量部署直接起不来），由使用点 fail-closed。

**修改** `.env.example`（`L40-52` 区域）：新增 `ODAP_SECRET_MASTER_KEY=` 并注明用途与生成方式（`openssl rand -base64 32`）。

**修改** `compose.yaml`（api 服务 env 区，`L135` 附近）：新增 `ODAP_SECRET_MASTER_KEY: ${ODAP_SECRET_MASTER_KEY:-}`。

### P1 —— 迁移 000029（新建）

**新建** `migrations/platform/000029_add_endpoint_credential_ciphertext.sql`：

```sql
ALTER TABLE llm.endpoints
    ADD COLUMN IF NOT EXISTS credential_ciphertext BYTEA,
    ADD COLUMN IF NOT EXISTS credential_masked     TEXT,
    ADD COLUMN IF NOT EXISTS credential_updated_at TIMESTAMPTZ;

-- MOCK 端点不得有任何形式的凭据
ALTER TABLE llm.endpoints DROP CONSTRAINT IF EXISTS ck_endpoints_mock_no_credential;
ALTER TABLE llm.endpoints ADD CONSTRAINT ck_endpoints_mock_no_credential
    CHECK (deployment_type <> 'MOCK'
           OR (credential_ref IS NULL AND credential_ciphertext IS NULL AND credential_masked IS NULL));

-- HTTP 端点必须有且仅有一个凭据来源
ALTER TABLE llm.endpoints DROP CONSTRAINT IF EXISTS ck_endpoints_single_credential_source;
ALTER TABLE llm.endpoints ADD CONSTRAINT ck_endpoints_single_credential_source
    CHECK (deployment_type <> 'HTTP'
           OR ((credential_ref IS NOT NULL) <> (credential_ciphertext IS NOT NULL)));

COMMENT ON COLUMN llm.endpoints.credential_ciphertext IS
    'AES-256-GCM 信封密文（version||nonce||ct+tag，AAD 绑定 endpoint_id）。明文密钥永不进入此列之外的任何位置（SQL 参数/审计/日志/SSE）。';
COMMENT ON COLUMN llm.endpoints.credential_masked IS
    '供界面展示的打码值（如 sk-****6e22）。由服务端写入，永不由客户端提供。';
```

**不回填**存量数据（存量 HTTP 端点仍是 `credential_ref` 一条路径，CHECK 允许）。

### P2 —— store 层：加密写入、只回打码

**修改** `internal/api/store/store.go`：

- `Store` 结构体（`L32-34`）新增 `cipher *secretbox.Cipher`。

**修改** `internal/api/store/model_providers.go`：

- `CreateModelProviderInput`（`L22-34`）新增 `APIKey string`（明文，仅在本次请求内存中存活）。
- `CreateModelProvider`（`L123-222`）：HTTP 分支改为「`api_key` 与 `credential_ref` **二选一，至少一个**」：
  - 给 `api_key` → **必须先拿到 cipher**：`s.cipher == nil` → 返回 `CodeUnavailable`（"服务端未配置主密钥 ODAP_SECRET_MASTER_KEY，无法加密存储密钥"）——fail-closed，绝不落明文。
  - 加密封装后，`credential_ciphertext = $x`、`credential_masked = secretbox.Mask(api_key)`、`credential_updated_at = now()`，且 `credential_ref` 写 NULL。
  - 给 `credential_ref` → 保持现状（存变量名）。
  - INSERT 语句增列；**`api_key` 明文只以「已加密后的 []byte」进入 SQL 参数**（满足 F6）。
- 校验：`api_key` 与 `credential_ref` **同时提供** → 400（来源必须唯一，与 CHECK 对齐）。
- MOCK 分支继续禁止二者。

**修改** `internal/api/store/model_endpoints.go`：

- `UpdateModelEndpoint` 签名从 7 个裸参数改为**结构体**（避免继续加参数导致调用点错位）：
  ```go
  type UpdateModelEndpointInput struct {
      EndpointName   *string
      DeploymentType *string
      RegionCode     *string
      BaseURL        *string
      CredentialRef  *string
      APIKey         *string // 三态见下
      Status         *string
  }
  ```
- 密钥三态（指针区分「未提供」与「提供空串」）：
  - 字段**缺失**（nil）→ 不改密钥。
  - **非空新值** → 加密替换（`credential_ciphertext` 新值、`credential_masked` 重算、`credential_ref` 置 NULL）。
  - **显式空串** → 清空密钥，并要求同时提供非空 `credential_ref`（否则 HTTP 端点失去唯一凭据来源 → 400）。
- `getEndpoint`（`L249-261`）与 `scanEndpoint`（`L264-273`）、`RETURNING`（`L179-180`）：增列 `credential_masked`、`(credential_ciphertext IS NOT NULL) AS has_credential`；**绝不 SELECT `credential_ciphertext` 本体**。

## 泄密面清单（必须逐项确认无明文）

1. **SQL 参数**（F6）—— 明文必须先加密再作为参数；`credential_ciphertext` 是唯一落库形态。
2. **审计 `audit.audit_events`**（F5）—— payload 只含 `has_credential` / `credential_masked`，不含 `api_key`，也**移除** `credential_ref` 原文回显。
3. **SSE 广播** —— payload 同上。
4. **日志** —— `newProvider` / `Probe` 的错误消息只允许出现变量名或端点名，不得拼接密钥。
5. **HTTP 响应** —— 只回 `credential_masked` / `credential_source` / `has_credential`。
6. **`llm-check` / 启动日志** —— 打印 `excluded` 原因时不得带密钥。
7. **供应商错误回显**（探针）—— `vendor_error_snippet` 回显前二次脱敏。

## Assumptions & Decisions

- **不实现网关热重载**：仍要求保存后重启 API（F1）；页面明示。热重载涉及装配生命周期改造，超出本次设计范围。
- **主密钥非必填**：`ODAP_SECRET_MASTER_KEY` 缺省时，仅"用 `api_key` 创建/更新"的路径 fail-closed 返回 503；既有 env 引用路径不受影响，保证存量部署不被本次改动打断。
- **`credential_masked` 只由服务端写**：客户端**永远不能**提交该字段（否则可伪造打码值）。
- **探针不写账本**：探针是"录入前的连通性检查"，不是业务推理；写成账本会污染对账与预算（F-治理链）。
- **env 引用路径的响应不回显变量名**：只回 `credential_source=ENV_REF`，因为变量名本身即部署环境细节。
- **不新增 `model_revisions` 管理 API**：用户已决策不要求；无版本端点保持"合法中间态 + 「不参与路由」徽标"（F4）。
- **`AddModelEndpoint` 与 `DeleteModelEndpoint` 的 409 保护不改**：`model_revisions`/`usage_ledger` 两道保护经确认为正确，本次仅改凭据列相关逻辑。
